# 2라운드 콘티 A — 단일 원형 전장

첫 번째 콘티를 바탕으로 만든 **로우폴리 공간 시안**이다. 2라운드 승자 연전과
추후 3라운드 3대3 결전에서 공용으로 검토할 수 있다. 크기와 엄폐물은 검증안이며
현재 캐릭터 이동속도를 최종 사양으로 가정하지 않았다.

## 구성과 크기

| 공간 | 시안 치수 | 내용 |
| --- | --- | --- |
| 외곽 원형 구역 | 지름 80m | 경계벽과 조경. 기초석 돌출까지 포함하면 약 80.9m |
| 중앙 전투 공간 | 지름 40m | 중앙을 비우고 가장자리에 대칭 엄폐물 2개 |
| 팀 대기·상점 공간 | 각각 지름 12m | 좌측 A팀, 우측 B팀, 팀당 대기 위치 3개 |
| 대기실 연결부 | 폭 4m | 중앙 전장 출입문 2개와 별도로 편집 가능 |
| 결투 출전 위치 | 두 위치 간 26m | A/B 각각 1개. 3대3용 위치는 팀당 3개 별도 제공 |

팀 공간에는 상점 모형, 상점 상호작용 기준점, 출전 선택용 GO 발판을 배치했다.
GO는 아직 공간 표시에 불과하며 상점·출전·대기 시간·라운드 로직은 없다.
외곽 조경 영역은 전투 동선으로 의도한 공간이 아니다. 최종적으로 대기실 이탈,
전장 경계, 점프·이동기와 투사체 통과 규칙은 게임 로직과 함께 정한다.

## 수정 단위와 기능 범위

지면, 벽, 엄폐물, 장식, 안내 글자, 상점 소품, 팀 대기실, 연결부, 출입문을 분리했다.
엄폐물은 윗판까지 `Optional_Cover`에 묶었다. 각 연결부는 바닥·난간·포장선을
하나의 FBX로 내보내므로 함께 제거하거나 교체할 수 있다.

문은 중심 피벗을 가진 독립된 StaticMeshActor이며 현재 닫힌 정적 모형이다.
문을 열거나 선수를 이동시키는 기능은 아직 없다. 스폰은 `TargetPoint` 기준점이다.
이번에는 PlayerStart, 상점 UI, 전투, 자기장, 카운트다운, 승패 판정을 구현하지 않았다.
바닥·벽·엄폐물·상점 소품·문에는 충돌이 있고, 장식과 바닥 글자는 충돌하지 않는다.
충돌은 시안 검토를 위한 complex-as-simple 방식이며 최종 게임용 최적화는 별도다.

## 검사

`Geometry_Verification.json`: 실제 Blender 메시를 대상으로 출전 위치, 대기 위치,
발판과 연결 동선에 바닥이 있고 벽이 침범하지 않는지 수직 광선으로 검사한다.
닫힌 문은 열린 동선 검사에서 제외하고 별도의 수평 광선으로 차단 상태를 확인한다.
양 팀의 출전 위치에서 가까운 문·먼 문까지의 직선 거리도 비교한다.

`Unreal_Verification.json`: 저장한 레벨을 다시 열어 메시 개수, 기준점, 단위 변환,
각 메시의 경계·피벗·배치, 재질 연결과 충돌 프로필을 검사한다.
미리보기는 Blender 렌더다. Unreal 검사는 NullRHI 백그라운드 실행이므로 실제
게임 화면, NavMesh, 캐릭터 이동과 전투 밸런스가 검증된 것은 아니다.

생성기는 프로젝트의 `Scripts/Blender/CreateRound02Concepts.py`, Unreal 임포터는
`Scripts/CreateRound02Concepts.py`다. Blender 재생성은 해당 출력 파일을 다시 쓴다.
수동 편집한 Blender 원본은 다른 이름으로 보관한다. Unreal 임포터의 기본 실행은
이미 생성된 레벨을 보존하고 재검증한다. `-Round02RefreshAssets`는 생성 에셋만
명시적으로 다시 임포트하므로 수동 수정된 메시·재질이 있다면 먼저 보관해야 한다.
