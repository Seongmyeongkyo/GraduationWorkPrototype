# 2라운드 콘티 B — 세 전장 동시 결투와 합류

두 번째 콘티를 바탕으로 만든 **로우폴리 공간 시안**이다. 세 원형 전장을
삼각형으로 연결하고, 전장 선택을 위한 팀별 대기·상점 공간을 별도로 마련했다.
이 방식을 채택한다면 3라운드에서는 콘티 A 전장을 사용하는 구상이다.

## 구성과 크기

| 공간 | 시안 치수 | 내용 |
| --- | --- | --- |
| 원형 전장 | 각각 지름 24m, 총 3개 | 금색 1번, 청록색 2번, 보라색 3번 |
| 전장 중심 간 거리 | 세 변 모두 42m | 정삼각형 배치 |
| 통로 | 폭 5m, 원 경계 사이 18m | 연결부 겹침을 포함한 실제 바닥 메시 길이는 19m |
| 통로 문 | 총 6개, 각 전장에 2개 | 각 문을 별도 메시·중심 피벗으로 제공 |
| 팀 대기·상점 공간 | 각각 지름 12m | 팀당 상점 1개, 선택 발판 3개, 대기 위치 3개 |
| 결투 출전 위치 | 전장마다 두 위치 간 15m | 양 팀의 출전 위치 총 6개 |

출전 위치와 엄폐물은 전장마다 120도씩 회전한다. 각 전장에서 A/B팀의 가까운 문,
먼 문까지의 거리가 같도록 배치했다. 전장마다 소형 엄폐물 2개를 가장자리에 두고
중앙 전투 공간을 비웠다. 이는 초기 공간 조건의 대칭성 검사이며 전투 밸런스 확정은 아니다.

대기실은 전장과 물리적으로 이어지지 않은 별도 섬이다. 플레이어가 상점을 이용하고
1/2/3번 발판으로 가고 싶은 전장을 표시한 뒤, 정해진 시점에 선택 전장으로 이동하는
구상을 표현했다. 순간이동, 선택 확정, 중복 선택 처리, 타이머, UI는 아직 구현하지 않았다.

## 문 개방 설계 시 주의할 점

콘티의 빨간 벽은 닫힌 붉은 문 모형으로 표현했다. 현재는 정적 충돌 메시다.
게임 로직에서는 **승자가 아직 결투 중인 다른 전장으로 들어갈 수 있어야 한다.**
양 끝 문을 모두 “그 문이 속한 전장의 결투가 끝난 뒤에만 개방”하면 이 목적을
충족하지 못한다. 출발 전장의 승자에게 통로와 도착 전장의 진입을 허용하고,
진행 중인 전장의 선수 이탈 여부는 별도로 판정할 수 있도록 게이트 기준점을 분리했다.

특정한 문 개방 방식, 일방통행, 통로 대신 포털을 사용할지는 확정하지 않았다.
각 통로는 바닥·난간·포장선을 함께 묶었고 문은 6개 모두 독립되어 있으므로 나중에
이동 방식을 바꾸기 쉽다. 문틀과 문턱은 전장 쪽 장식·벽 그룹에 남는다.

Blender의 저장된 시작 뷰와 `Camera_Top`은 +X가 위쪽인 탑뷰다.
숫자패드 7은 Blender 기본 방향으로 돌아간다. 개별 오브젝트와 컬렉션은 편집 가능하다.
Unreal에서는 `Round02/Geometry/replaceable_corridor` 폴더에 통로 3개,
`Round02/Geometry/transfer_gate` 폴더에 문 6개를 배치했다.
`Round02/Layout`의 TargetPoint에 전장·팀·선택 목적지 등의 태그를 기록했다.

바닥·벽·엄폐물·상점 소품·문은 충돌하고 장식과 글자는 충돌하지 않는다.
충돌은 검토용 complex-as-simple 방식이다. PlayerStart, 실제 팀 스폰, 상점,
전장 선택, 카운트다운, 승패, 자기장, 문 제어와 합류 권한 처리는 추후 구현한다.

## 축 방향·팀 상점·다리 치수

화면 위쪽의 1번 전장을 북쪽으로 삼아 Unreal **+X=위, +Y=오른쪽**으로 정렬했다.
Blender는 **+X=위, -Y=오른쪽**이고 m 단위다. UE는 cm 단위다.
메시·독립 게이트 피벗·배치 기준점·카메라와 Layout.json에 같은 변환을 적용했다.

| 구역 | Unreal 중심 좌표 (cm) |
| --- | --- |
| 1번 전장 / 위 | `(2424.87, 0, 0)` |
| 2번 전장 / 좌하단 | `(-1212.44, -2100, 0)` |
| 3번 전장 / 우하단 | `(-1212.44, 2100, 0)` |
| A팀 상점·대기 / 좌측 | `(2400, -4300, 0)` |
| B팀 상점·대기 / 우측 | `(2400, 4300, 0)` |

양 팀 구역은 각각 지름 12m의 원형 공간이며, 상점 모형·대기 위치 3개·전장 선택 발판 3개를 갖춘다.
두 상점은 기존 원본에도 있었으며, 이번에 실제 메시·표시 상태와 좌우 대칭을 확인하고
두 구역이 모두 들어오는 정면 사선 카메라로 정리했다.

다리 3개는 **바닥 메시 길이 19m, 폭 5m**로 동일하다. 전장 원 경계 사이 빈 거리는 18m이고,
양 끝이 각 전장에 0.5m씩 겹쳐 바닥 틈을 막는다. 전장 중심 간 거리는 세 변 모두 42m다.
회전된 메시의 축 정렬 바운딩 박스 길이는 서로 다르므로, 각 다리 진행 방향으로 실제
바닥 버텍스를 투영해 길이·폭을 검사한다.

Unreal Outliner의 `Round02_NorthTopCamera`를 우클릭 → Pilot하면 +X 위쪽 탑뷰를 볼 수 있다.
`Round02_OverviewCamera`는 양 팀 상점을 모두 보여주는 사선 시점이다.
이미 열려 있던 에디터는 레벨을 다시 불러온다.
실측·대칭·카메라 방향 검사 결과는 `NorthAxis_Blender_Verification.json`,
`NorthAxis_Unreal_Verification.json`에 기록한다.

## 검사와 재생성

`Geometry_Verification.json`은 실제 메시에 대한 801개 바닥·동선 광선 검사,
6개 닫힌 문의 차단 검사, 팀별 문 접근 거리 비교를 기록한다.
동선 검사는 문을 열린 것으로 가정해 제외하고, 통로 중심에서 좌우 1.8m까지 검사한다.

`Unreal_Verification.json`은 저장 후 재로딩, 메시·기준점 수, 단위·피벗·경계·배치,
재질과 충돌 설정을 검사한다. 미리보기는 Blender 렌더이고 Unreal은 NullRHI로
검사했으므로 실제 게임 화면·이동·NavMesh·밸런스 테스트를 대체하지 않는다.

생성기는 `Scripts/Blender/CreateRound02Concepts.py`이며 `-- --concept=B`로
이 안만 재생성할 수 있다. `--no-render`는 렌더를 생략하고 `--render-only`는
저장된 Blender 파일의 미리보기만 다시 만든다. 수동 편집본은 다른 이름으로 보관한다.
UE 임포터 `Scripts/CreateRound02Concepts.py`의 기본 실행은 완성된 레벨을 보존한다.
`-Round02RefreshAssets`는 메시·재질만 다시 임포트하는 명시적 옵션이다.
